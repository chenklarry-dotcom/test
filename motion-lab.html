Before writing animation code

The decision framework

Four questions, answered in order, before a single line of CSS gets written.

01

Should it animate?

Something seen 100+ times a day (shortcuts, palette toggles) gets no animation, ever. Rare, first-time moments can carry delight.

02

What's the purpose?

Spatial consistency, state indication, feedback, or preventing a jarring change. "It looks cool" isn't a purpose if it plays often.

03

What easing?

Entering or exiting → ease-out. Moving on screen → ease-in-out. Hover/color → ease. Constant motion → linear.

04

How fast?

Button feedback 100–160ms. Dropdowns 150–250ms. Modals up to 500ms. UI animation stays under 300ms — full stop.

Entering / exiting --ease-out: cubic-bezier(0.23, 1, 0.32, 1);
Moving on screen --ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
Drawers (Ionic curve) --ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);

Live demos

Seven components, each built to one specific rule below it.

01

Button feedback

Press it.

transform: scale(0.97) on :active, 160ms ease-out. Confirms the interface heard you.

02

Origin-aware popover

Open the menu.

Scales from 0.95 — never scale(0) — anchored to its trigger, not centered.

03

Interruptible toast

Click it a few times, fast.

A transition, not a keyframe — rapid clicks retarget smoothly instead of restarting from zero.

04

Centered modal

Open the dialog.

The one exception to origin-aware scaling: modals stay transform-origin: center.

05

Sliding tab indicator

Switch tabs.

Moves via translateX(N * 100%) — percentages are relative to its own size — with ease-in-out since it travels on screen.

Hold to delete

clip-path fills over 2s linear while held; release snaps back in 200ms ease-out. Deliberate press, instant response.

The required review format

Review checklist

The skill requires reviews as a Before/After/Why table — never a bulleted list. A few rows from it:

BeforeAfterWhy
transition: all 300ms transition: transform 200ms ease-out Specify exact properties; all animates things you didn't intend to.
transform: scale(0) scale(0.95) + opacity: 0 Nothing in the real world appears from nothing.
ease-in on dropdown ease-out, custom curve ease-in delays the movement the user is watching most closely.
No :active state scale(0.97) on press Buttons must feel responsive to being pressed.
Animation on keyboard action Removed entirely Actions repeated 100+ times a day should never wait on motion.
